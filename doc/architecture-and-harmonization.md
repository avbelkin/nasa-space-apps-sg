# Architecture & Harmonization Design Notes

This repository implements the [Harmonization of MODIS and VIIRS Hot Spots](./README.md) solution as a decoupled static SPA and containerized API.

## System Split

### 1. Frontend (`ui/` — Pure React + TypeScript + Vite on GitHub Pages)

- **Public Availability**: Publicly accessible on GitHub Pages at [https://avbelkin.github.io/nasa-space-apps-sg](https://avbelkin.github.io/nasa-space-apps-sg), deployed via [deploy-ui.yml](../.github/workflows/deploy-ui.yml).
- **Earth-First Mapping Engine (`maplibre-gl`)**: Keyless **MapLibre GL JS** canvas defaulting to a **3D `globe` projection** (with an optional 2D `mercator` toggle) over **EOX Sentinel-2 Cloudless (`s2cloudless-2025_3857`)** raster WMTS imagery (`{z}/{y}/{x}.jpg` with required EOX/Copernicus attribution) to visualize active-fire hotspots, typical seasonal activity bands, and current calendar anomaly departures directly on Earth.
- **Two-Tier CSS Grid Layout**:
  - **Outer Controls Wrapper (`.app-frame`)**: CSS Grid page shell wrapping perimeter controls *around* the map:
    - `topbar` (`<header>`) — Standalone **Earth Fire Calendar** application title (provisional title; no NASA branding or logos), view mode switcher (`Anomaly vs. Typical`, `Seasonal Dynamics`, `Sensor Harmonization`), and Cloud Run backend API health badge/trigger.
    - `timeline` (`<section>`) — Bottom seasonal/calendar scrubber (`Jan`–`Dec`) displaying the typical historical curve alongside current activity and anomaly classification badges.
    - `sidepanel` (`<aside>`) — Regional seasonal-fit vs. anomaly inspector, live 24h NASA FIRMS hotspot metrics, live satellite orbits, deployment diagnostics, and a `<footer>` block exposing factual data attribution (`NASA FIRMS` live hotspots & sensors, `CelesTrak` orbital TLEs, and `EOX/Copernicus` Sentinel-2 basemap) plus a NASA non-affiliation notice.
    - `legend` (`<section>`) — Bottom outer-frame legend bar below `timeline` and `sidepanel` summarizing active-fire FRP/sensor or anomaly glyphs, nadir/wide swath swatches, MODIS/VIIRS track symbols, current coordinates/zoom, and geolocation status outside the map stage.
  - **Inner Map CSS Grid Container (`.map-stage`)**: Dedicated CSS Grid stage holding the full-bleed MapLibre canvas across all tracks (`grid-column: 1 / -1; grid-row: 1 / -1`) alongside named overlay grid areas (`hud-top-start`, `hud-top-end`, `hud-bottom-start`, `hud-bottom-end`) for floating HUD controls, hover/pinned fire spot inspection cards (`hud-bottom-start`), and the `SAT` overpass freshness card (`hud-bottom-end`) positioned *over* the map without brittle pixel offsets, keeping unobstructed map tracks directly interactive, plus MapLibre's `attributionControl` displaying basemap, `NASA FIRMS`, and `CelesTrak` attributions.
- **Sensor Transparency & Accessible Visuals**: Toggle between Harmonized, MODIS (1 km), and VIIRS (375 m) layers with explicit text labels and symbols alongside accessible color ramps so researchers and responders never rely on color alone.
- **URL Hash, LocalStorage & Geolocation State**: Viewport (`z`, `lat`, `lng`) and active UI controls (`mode`, `sensor`, `proj`, `month`, `orbits`, `clouds`, plus extensible feature parameters such as `fires=0`) sync continuously into `window.location.hash` and `window.localStorage` (`nasa_fire_calendar_url_hash`), restoring in `hash` → `localStorage` → default order. A HUD **My Location** control (and one-time initial load prompt only when no URL hash or saved `localStorage` state exists) jumps to the user's coarse browser geolocation capped at default max zoom `z7`.
- **Day/Night Terminator Satellite Clouds Layer (`satelliteCloudLayer.ts`)**: Renders live `258×258` (`256px` + `1px` gutter) `VIS/IR` cloud PNG tiles (`R = 10.8 µm IR`, `G = solar VIS`) via a MapLibre GL JS WebGL2 `CustomLayerInterface` supporting both `globe` and `mercator` projections, NW cloud-top embossing, day/night terminator color blending, zoom fade (`z5.25` → `z9`), and 5-minute visibility-aware refresh, stacked above the basemap and underneath all satellite orbits, swaths, and hotspots.
- **Live Animated Active-Fire Spots (`fireSpots.ts`, `fireSpotsAnimation.ts`)**: Streams compact 24h NASA FIRMS detections (`MODIS_NRT` + `VIIRS_NOAA20_NRT` + `VIIRS_NOAA21_NRT`) every 15 minutes from `/api/fires/spots`, applying hierarchical `z1`–`z7` spatial decluttering above `z1` and rendering a crisp core circle layer scaled by FRP (`1–250 MW -> 0.5–1.5x`) and shaded by confidence (`25–100% -> 0.6–1.0`) above 4 spatial phase-cohort pulse layers (`80ms` tick modulated by 24h linear activity decay `[1 -> 0]` and `sin(2π * cycles + phase)` frequency sweep). Automatically pauses pulsing after 5 minutes of user inactivity, on hidden tabs, when scrolled out of the viewport, or when `prefers-reduced-motion: reduce` is enabled while preserving static spot legibility, and supports 8 px hover/click tooltips (individual list for 1–3 spots; aggregated total/peak FRP summary for 4+).
- **Live MODIS & VIIRS Orbital & Swath Overlay**: Renders time-bound satellite ground tracks (solid past `-45m`, dashed future `+90m`, split across the `±180°` antimeridian), heading-locked dual instantaneous sensor scan swaths in `extremum` palette styling (wide swath `#f49a74` dashed `4,6` at `0.035` fill / `0.12` stroke below nadir swath `#92b4de` at `0.14` fill / `0.32` stroke; `400 km` nadir and `2,330 km` MODIS / `3,040 km` VIIRS wide swaths), rotated spacecraft SVG badges alongside nadir position markers, and a `SAT` viewport overpass freshness HUD (`ready` / `processing`, `lag ~Xm`, `next <Sat> ~Xm`), animated every `500ms` along the fetched CelesTrak orbital window.
- **Social Link Preview & Canonical Metadata**: Configures Open Graph (`og:*`) and X/Twitter (`summary_large_image`) tags in `ui/index.html` backed by a `1200×630` hero preview thumbnail (`ui/public/og-preview.png`) with build-time `VITE_SITE_URL` resolution in `ui/vite.config.ts` so deployed GitHub Pages unfurls use absolute HTTPS URLs without NASA branding.

### 2. Backend (`backend/` — ASP.NET Core `.NET 10` Container on Google Cloud Run)

- **CelesTrak TLE Caching, Swath Geometry & Overpass Freshness (`Satellites/`)**: Downloads TLE catalogs from CelesTrak (`GROUP=resource` for MODIS Terra/Aqua; `GROUP=weather` for VIIRS NOAA-20/NOAA-21), caches them for 12 hours in memory with embedded fallback TLEs, propagates J2 secular LEO trajectories, builds `49`-vertex (`12`-segment edge) high-latitude/polar-clamped nadir and wide swath polygons (`SatelliteSwathBuilder`), and evaluates 10-day lookback / 24-hour lookahead viewport overpass freshness (`SatelliteOverpassEvaluator`).
- **FIRMS Ingestion & Caching Proxy (`Firms/`)**: Directly queries the official NASA FIRMS REST Area API (`api/area/csv/{MAP_KEY}/{source}/{world|bbox}/{days}`) across `MODIS_NRT`, `VIIRS_NOAA20_NRT`, and `VIIRS_NOAA21_NRT`, caching area snapshots in `IMemoryCache` for 20 minutes and slicing to a rolling 24h window ("as of now", avoiding UTC calendar-day gaps) with 2-minute stale fallback if upstream refreshes fail, response compression, and server-side `FIRMS_MAP_KEY` isolation.
- **Spatiotemporal Harmonization Pipeline**:
  1. **Spatial Gridding**: Maps point detections onto a uniform grid (cell size ≥ 1 km, e.g. fixed equal-area / H3 / degree grid) while accounting for MODIS/VIIRS `scan` × `track` footprint growth toward scan edges.
  2. **Temporal Binning & Deduplication**: Aggregates detections per grid cell within daily/pentad windows to eliminate artificial inflation from multiple same-day satellite overpasses (Terra, Aqua, Suomi NPP, NOAA-20, NOAA-21).
  3. **Cross-Sensor Calibration**: Uses the post-2012 MODIS–VIIRS overlap period to align active-fire cell density and Fire Radiative Power (`FRP`) quantiles into a continuous multi-decade metric.
- **Satellite Cloud Proxy (`Clouds/`)**: Proxies `https://layers.extremum.org/v3/weather/satellite/{z}/{x}/{y}.png` (`z` `1..7`) with explicit `Referer`, `User-Agent`, and per-instance `gis-uuid` cookie plus `IMemoryCache` and in-flight request deduplication so client globes avoid upstream rate limits.
- **REST API Endpoints**:
  - `GET /health` — Cloud Run readiness/liveness probe.
  - `GET /api/status` — Service metadata and environment diagnostics.
  - `GET /api/fires/spots` — Compact rolling 24h (configurable `hours=1..48`, `sensor=harmonized|modis|viirs`, `bbox=w,s,e,n` or `world`) active-fire spots feed queried directly from NASA FIRMS Area API (`api/area/csv`) and cached for 20 minutes (`MODIS_NRT`, `VIIRS_NOAA20_NRT`, `VIIRS_NOAA21_NRT`).
  - `GET /api/fires/spots.geojson` — GeoJSON FeatureCollection projection of the cached rolling active-fire Area API snapshot.
  - `GET /api/satellites/orbits` — Time-bound orbital ground tracks, nadir position, heading, speed, swath parameters, computed `swaths` (`nadir`/`wide`), and `satelliteHud` overpass freshness entries (optional `lat`/`lng` query parameters) for Terra, Aqua, NOAA-20, and NOAA-21.
  - `GET /api/weather/satellite/{z}/{x}/{y}.png` — Cached `258×258` live `VIS/IR` satellite cloud tile proxy backed by `layers.extremum.org`.
  - `GET /api/anomalies/summary` *(planned)* — Regional & AOI current situation summary compared against historical calendar baselines (`fitsTypical`, `anomalyScore`, `zScore`, percentile).
  - `GET /api/seasonal/profile` *(planned)* — Harmonized multi-decade monthly/pentad climatology vs. current-year trajectory for the bottom seasonal scrubber and side inspector.
  - `GET /api/hotspots` *(planned)* — Spatial GeoJSON/vector hotspot clusters and harmonized grid cells for MapLibre rendering within a selected date window and sensor filter.
