# Architecture & Harmonization Design Notes

This repository implements the [Harmonization of MODIS and VIIRS Hot Spots](./README.md) solution as a decoupled static SPA and containerized API.

## System Split

### 1. Frontend (`ui/` — Pure React + TypeScript + Vite on GitHub Pages)

- **Public Availability**: Publicly accessible on GitHub Pages at [https://avbelkin.github.io/nasa-space-apps-sg](https://avbelkin.github.io/nasa-space-apps-sg), deployed via [deploy-ui.yml](../.github/workflows/deploy-ui.yml).
- **Earth-First Mapping Engine (`maplibre-gl`)**: Keyless **MapLibre GL JS** canvas defaulting to a **3D `globe` projection** (with an optional 2D `mercator` toggle) over **EOX Sentinel-2 Cloudless (`s2cloudless-2025_3857`)** raster WMTS imagery (`{z}/{y}/{x}.jpg` with required EOX/Copernicus attribution) to visualize active-fire hotspots, typical seasonal activity bands, and current calendar anomaly departures directly on Earth.
- **Two-Tier CSS Grid Layout**:
  - **Outer Controls Wrapper (`.app-frame`)**: CSS Grid page shell wrapping perimeter controls *around* the map (stacked below 60rem):
    - `topbar` (`<header>`) — **Earth Fire Calendar** title (provisional title; no NASA branding or logos), a one-line plain-language subtitle, and an always-visible **Sample data** badge; two lines (≤ 72 px) on a 375 px phone.
    - `timeline` (`<section>`) — Month strip: worldwide fire activity per month in a fixed 12-column grid (6 × 2 when narrow), each month a gray "typical" band and a "this year" bar on one 0–100 scale, ▲/▼ above months that depart from typical, the selected month's value, a current-month dot, and hover/focus tooltips (Escape hides them). Empty slots are reserved for a year axis, period selector and CSV export.
    - `sidepanel` (`<aside>`) — Area/Period readout (✕ or Escape clears a selected region), Harmonized | MODIS | VIIRS sensor segment, summary (the month worldwide or the selected region: status, typical vs. this year, delta, peak months, sensor agreement, note), regions sorted by size of departure, collapsed `<details>` for Satellites and Diagnostics (API status, Check API, TLE source), and a `<footer>` with one credit line (`NASA FIRMS`, `CelesTrak`, Extremum clouds, `EOX/Copernicus` Sentinel-2, NASA non-affiliation), collapsible "Sources and credits" and a small data-service indicator.
    - `legend` (`<section>`) — The map legend as a compact row (one inline flow, one or two lines on a laptop) below `timeline` and `sidepanel` (last on a phone), outside the map stage: the status marks drawn exactly as on the map (`StatusMark`), nadir/wide swath swatches and MODIS/VIIRS track swatches from `dataPalette.ts` while orbits are shown, "Your location" once located, and the current coordinates/zoom.
  - **Inner Map CSS Grid Container (`.map-stage`)**: The full-bleed MapLibre canvas spans all tracks under two HUD areas: `hud-top-end` holds a column of icon buttons (zoom, My Location with its error message beside it, reset view), a `2D | 3D` segment and the orbits and clouds toggles (folded into two columns on maps narrower than 36rem); `hud-bottom-end` (the map column, beside the control column so the two never stack on a short map) holds the satellite overpass freshness card while orbits are shown (a foldable card: open by default on maps at least 48rem wide, folded to its "Satellite passes" header on narrower maps so it does not hide marks at the default view), kept just above MapLibre's compact `attributionControl` (EOX/Copernicus basemap, `NASA FIRMS (sample data)`, `CelesTrak`, Extremum clouds) by tracking the control's height, so no HUD element overlaps the attribution in its collapsed or expanded state.
- **Sensor Transparency & Accessible Visuals**: The Harmonized / MODIS / VIIRS segment (ARIA radio group, arrow keys) filters the map, the panel and the satellite card. Status is shape plus color, on the map and in the legend from one definition (`statusMarks.ts`): ▲ above typical (orange), hollow ○ typical, ▼ below typical (dark blue, ≥ 3:1 lightness contrast to orange); one ±8-point classifier sets the status of regions and months. Data colors live in `dataPalette.ts`, one hue per meaning (MODIS satellites green, VIIRS magenta/violet); the team's fixed swath hues (pale blue nadir, pale orange wide) are kept there too and drawn at low opacity. Regions are selected from the list or by clicking a map mark. Focus styles, coarse-pointer touch targets, light/dark themes and `forced-colors` support are kept.
- **URL Hash, LocalStorage & Geolocation State**: Viewport (`z`, `lat`, `lng`) and controls (`mode`, `sensor`, `proj`, `month`, `orbits`, `clouds`, `region`, plus extensible feature parameters; one codec registry in `urlHashState.ts`) sync continuously into `window.location.hash`, and the same state without `month` into `window.localStorage` (`nasa_fire_calendar_state_v2`; the older `nasa_fire_calendar_url_hash` key, auto-written by earlier builds, is ignored). A URL hash wins; otherwise viewport, sensor, projection, orbits, clouds and region restore from storage. The month comes only from the hash, else it is the current month. Orbits and clouds are on by default. There is no geolocation prompt on load: the HUD **My Location** button jumps to the user's coarse browser position, capped at default max zoom `z7`.
- **Day/Night Terminator Satellite Clouds Layer (`satelliteCloudLayer.ts`)**: Renders live `258×258` (`256px` + `1px` gutter) `VIS/IR` cloud PNG tiles (`R = 10.8 µm IR`, `G = solar VIS`) via a MapLibre GL JS WebGL2 `CustomLayerInterface` supporting both `globe` and `mercator` projections, NW cloud-top embossing, day/night terminator color blending, zoom fade (`z5.25` → `z9`), and 5-minute visibility-aware refresh, stacked above the basemap and underneath all satellite orbits, swaths, and hotspots. Toggled from the map control column (`clouds` hash key).
- **Live MODIS & VIIRS Orbital & Swath Overlay**: Renders time-bound satellite ground tracks (solid past `-45m`, dashed future `+90m`, split across the `±180°` antimeridian), heading-locked dual instantaneous sensor scan swaths in `extremum` palette styling (wide swath `#f49a74` dashed `4,6` at `0.035` fill / `0.12` stroke below nadir swath `#92b4de` at `0.14` fill / `0.32` stroke; `400 km` nadir and `2,330 km` MODIS / `3,040 km` VIIRS wide swaths), rotated spacecraft SVG badges alongside nadir position markers, and a "Satellite passes" viewport overpass freshness card (latest pass per satellite, `ready` / `processing`, `~Xh delay`, `Next: <Sat> in ~Xm`), animated every `500ms` along the fetched CelesTrak orbital window. Picking a satellite flies to where it is at that moment.
- **Social Link Preview & Canonical Metadata**: Configures Open Graph (`og:*`) and X/Twitter (`summary_large_image`) tags in `ui/index.html` backed by a `1200×630` hero preview thumbnail (`ui/public/og-preview.png`) with build-time `VITE_SITE_URL` resolution in `ui/vite.config.ts` so deployed GitHub Pages unfurls use absolute HTTPS URLs without NASA branding.

### 2. Backend (`backend/` — ASP.NET Core `.NET 10` Container on Google Cloud Run)

- **CelesTrak TLE Caching, Swath Geometry & Overpass Freshness (`Satellites/`)**: Downloads TLE catalogs from CelesTrak (`GROUP=resource` for MODIS Terra/Aqua; `GROUP=weather` for VIIRS NOAA-20/NOAA-21), caches them for 12 hours in memory with embedded fallback TLEs, propagates J2 secular LEO trajectories, builds `49`-vertex (`12`-segment edge) high-latitude/polar-clamped nadir and wide swath polygons (`SatelliteSwathBuilder`), and evaluates 10-day lookback / 24-hour lookahead viewport overpass freshness (`SatelliteOverpassEvaluator`).
- **FIRMS Ingestion & Caching Proxy**: Fetches and caches NASA FIRMS archives / near-real-time API feeds server-side so `FIRMS_MAP_KEY` secrets remain protected on Cloud Run and client requests avoid rate-limit failures.
- **Spatiotemporal Harmonization Pipeline**:
  1. **Spatial Gridding**: Maps point detections onto a uniform grid (cell size ≥ 1 km, e.g. fixed equal-area / H3 / degree grid) while accounting for MODIS/VIIRS `scan` × `track` footprint growth toward scan edges.
  2. **Temporal Binning & Deduplication**: Aggregates detections per grid cell within daily/pentad windows to eliminate artificial inflation from multiple same-day satellite overpasses (Terra, Aqua, Suomi NPP, NOAA-20, NOAA-21).
  3. **Cross-Sensor Calibration**: Uses the post-2012 MODIS–VIIRS overlap period to align active-fire cell density and Fire Radiative Power (`FRP`) quantiles into a continuous multi-decade metric.
- **Satellite Cloud Proxy (`Clouds/`)**: Proxies `https://layers.extremum.org/v3/weather/satellite/{z}/{x}/{y}.png` (`z` `1..7`) with explicit `Referer`, `User-Agent`, and per-instance `gis-uuid` cookie plus `IMemoryCache` and in-flight request deduplication so client globes avoid upstream rate limits.
- **REST API Endpoints**:
  - `GET /health` — Cloud Run readiness/liveness probe.
  - `GET /api/status` — Service metadata and environment diagnostics.
  - `GET /api/satellites/orbits` — Time-bound orbital ground tracks, nadir position, heading, speed, swath parameters, computed `swaths` (`nadir`/`wide`), and `satelliteHud` overpass freshness entries (optional `lat`/`lng` query parameters) for Terra, Aqua, NOAA-20, and NOAA-21.
  - `GET /api/weather/satellite/{z}/{x}/{y}.png` — Cached `258×258` live `VIS/IR` satellite cloud tile proxy backed by `layers.extremum.org`.
  - `GET /api/anomalies/summary` *(planned)* — Regional & AOI current situation summary compared against historical calendar baselines (`fitsTypical`, `anomalyScore`, `zScore`, percentile).
  - `GET /api/seasonal/profile` *(planned)* — Harmonized multi-decade monthly/pentad climatology vs. current-year trajectory for the bottom seasonal scrubber and side inspector.
  - `GET /api/hotspots` *(planned)* — Spatial GeoJSON/vector hotspot clusters and harmonized grid cells for MapLibre rendering within a selected date window and sensor filter.
